# 스마트폰 진자 실험 웹앱 – 개발 명세서

> 사용자(교사)가 2026-11-14 준 원문. 결정 사항(이 사이트에 두기, Apps Script + 구글 시트)은 `docs/HANDOVER-2026-11-14.md` 참고.
> 이 문서는 Claude Code에 전달하는 개발 요구사항입니다. 1단계부터 순서대로 구현하고, 단계마다 동작을 확인한 뒤 다음 단계로 넘어가 주세요.

## 1. 프로젝트 개요

- **목적:** 고등학교 물리 실험 수업(단진자의 주기, 3~5차시)에서 비싼 전용 센서 대신 학생 스마트폰의 센서로 진자의 주기를 측정하고, 조원 노트북에서 데이터를 분석해 실험 보고서를 작성한다.
- **사용자**
  - 학생(조별 4명 내외): 스마트폰 1대로 측정, 각자 노트북으로 분석·보고서 작성
  - 교사: Google 시트에서 조별 데이터, 보고서, AI 사용 기록 확인
- **학습 목표:** 스마트폰 센서로 진자의 주기를 측정하고, T²–L 그래프로 중력가속도 g를 구해 오차 원인을 데이터로 설명할 수 있다.

## 2. 기술 구성 (권장)

| 구성 | 기술 | 이유 |
|---|---|---|
| 프론트엔드 | 순수 HTML/CSS/JS (빌드 도구 없이), Chart.js | 교사가 수정하기 쉬움 |
| 호스팅 | GitHub Pages | 무료, **HTTPS 필수**(센서 권한 조건) |
| 백엔드 | Google Apps Script 웹앱 | 서버 비용 없음, 시트에 바로 저장 |
| 저장소 | 교사의 Google 시트 | 교사가 데이터를 바로 확인 |
| AI | Apps Script에서 Claude API(또는 Gemini API) 호출 | **API 키를 브라우저에 노출하지 않음** |

- API 키는 Apps Script의 Script Properties에 저장한다. 프론트엔드 코드에 절대 넣지 않는다.
- 페이지 구성
  - `measure.html` – 스마트폰용 측정 화면
  - `report.html` – 노트북용 분석·보고서 화면
  - `teacher.html` (선택) – 교사용 조별 현황
  - `apps-script/Code.gs` – 백엔드

## 3. 단계별 구현 범위

### 1단계: 측정 앱 (`measure.html`)

**센서 수집**
- `DeviceMotionEvent`로 가속도(`accelerationIncludingGravity` x, y, z)와 회전 속도(`rotationRate` alpha, beta, gamma)를 함께 기록한다.
- iOS: 사용자가 "측정 시작" 버튼을 누를 때 `DeviceMotionEvent.requestPermission()`을 호출한다.
- 측정 중 화면이 꺼지지 않도록 Wake Lock API를 사용한다(미지원 시 안내 문구 표시).
- 샘플 간격이 일정하다고 가정하지 말고, 매 샘플의 실제 시각(`event.timeStamp` 또는 `performance.now()`)을 기록한다.
- 측정 시작 전 "가만히 두기" 3초 보정 단계로 축 방향과 중력 기준값을 확인한다(안드로이드와 iOS의 축 부호 차이 대응).

**주기 계산 (물리적으로 중요)**
- 폰이 추가 되어 흔들리면 줄 방향 가속도는 최저점을 지날 때마다 최대가 되므로 **최대점 간격 = T/2**다. 가속도 축으로 계산할 때는 반드시 이를 반영한다.
- 기본 계산은 **회전 속도(rotationRate)** 신호로 한다. 진자와 같은 진동수의 사인파가 나온다.
- 알고리즘
  1. 이동평균(창 크기 조절 가능)으로 잡음 제거
  2. 평균값을 빼서 0을 기준으로 맞춤
  3. 같은 방향으로 0을 지나는 시점을 선형 보간으로 구함
  4. 연속한 통과 시점 간격 = T, 여러 주기의 평균과 표준편차를 계산
- 학생이 측정할 주기 수(기본 10주기)를 정할 수 있게 한다.
- 고급 옵션: FFT로 구한 진동수 비교

**그래프와 표**
- 시간–가속도, 시간–회전 속도 그래프(Chart.js). 데이터 점을 표시한다.
- 마우스를 올리면(노트북) 또는 터치하면(폰) 시간과 값이 툴팁으로 표시된다.
- 계산에 쓴 통과 시점을 그래프 위에 다른 색 점으로 표시한다.
- 아래에 데이터 표(시트 형태): 시간, 각 축 값. 주기 계산 결과 표: 회차, 주기.

**실험 조건 입력**
- 조 번호, 줄 길이 L(m), 진폭(°), 비고. 학생 이름은 받지 않는다.

**내보내기**
- CSV 다운로드(원본 데이터 + 조건 + 계산 결과).

### 2단계: 분석 화면 (`report.html`)

- CSV 불러오기(1단계 파일), 여러 측정(여러 줄 길이)을 한 표로 모은다.
- 표: L, T(평균), T 표준편차, T².
- **T²–L 그래프와 최소제곱 직선:** 기울기 → g = 4π² / 기울기, 절편 → 무게중심 오프셋 d.
  - 모델: T² = (4π²/g)(L + d). 폰의 무게중심까지의 거리를 몰라도 기울기로 g를 구할 수 있음을 화면에 설명한다.
- g의 오차율(기준값 9.80 m/s², 교사가 지역 값으로 바꿀 수 있게).
- 비교 실험 지원: 진폭–T, 질량–T 그래프.
- **모든 계산(추세선, g, 오차율)은 코드로 한다. AI에게 계산을 맡기지 않는다.**
- 그래프 점에 마우스를 올리면 값 툴팁 표시.

### 3단계: 조별 데이터 공유

- 조 코드(예: 반-조 번호 + 4자리 숫자)로 방을 만든다.
- 폰의 측정 결과를 Apps Script로 보내 시트에 저장하고, 같은 조 코드를 입력한 노트북이 불러온다.
- 서버 연결이 안 될 때를 대비해 CSV 내보내기/불러오기를 항상 함께 제공한다.
- QR코드는 조 코드 또는 불러오기 링크 전달용으로만 쓴다(원본 데이터는 QR에 담지 않는다).

### 4단계: 실험 보고서와 AI 피드백

보고서 항목: 주제, 목적, 이론, 준비물, 방법(실험 단계), 데이터 분석, 결론 및 검토.

**원칙: AI는 대신 써 주지 않고 피드백과 질문을 준다. 학생이 먼저 쓰고 AI에게 검토를 요청한다.**

| 항목 | AI 기능 | 시스템 프롬프트 방향 |
|---|---|---|
| 이론 | 학생 초안에서 빠진 개념을 질문으로 지적 | 정답을 써 주지 말고 질문 2~3개로 안내, 교과서 개념 범위 |
| 방법 | 실험 단계의 실현 가능성, 변인 통제 검토 | 독립·종속·통제 변인 표를 학생이 채운 뒤 검토 |
| 데이터 분석 | 코드로 계산한 결과를 받아 해석 질문 | 계산은 하지 말고 그래프 의미를 묻기 |
| 결론 및 검토 | 학생이 쓴 오차 원인이 데이터와 맞는지 검토 | 일반론("공기저항")이면 데이터 근거를 요구 |

**프롬프트 입력칸 방식 (AI 호출 구조)**
- 보고서 각 항목 아래에 **프롬프트 입력칸**과 "AI에게 묻기" 버튼을 둔다.
- AI는 프롬프트 입력칸에 내용이 있을 때만 동작한다. 입력칸이 비어 있으면 버튼을 비활성화한다. 학생이 요청하지 않았는데 AI가 보고서를 자동으로 읽거나 검토하지 않는다.
- AI에게 보내는 내용
  1. 프롬프트 입력칸의 내용(필수)
  2. 학생이 체크한 참고 자료(선택): 해당 항목의 보고서 초안, 코드로 계산한 분석 결과(표, g값, 오차율)
- 버튼을 누르면 프롬프트, 함께 보낸 참고 자료 종류, AI 답변, 시각, 조 코드, 보고서 항목을 `ai_logs` 시트에 **자동으로 저장**한다. 학생이 따로 기록할 필요가 없다.
- AI 답변 아래에 **"검증·수정 메모"** 칸을 둔다(선택). 학생이 AI 답을 어떻게 확인하고 고쳤는지 적으면 같은 기록에 함께 저장한다.
- 프롬프트 입력칸 옆에 예시 문장을 흐리게 보여 준다. 예: "내가 쓴 오차 원인이 측정 데이터와 맞는지 검토해 줘. 내 생각은 ~이야."
- AI 호출은 모두 Apps Script를 거친다. 조 코드당 호출 횟수 한도를 둔다.
- 보고서는 항목별로 자동 저장(시트)하고, 최종 제출 버튼으로 마감한다.
- 내보내기: 보고서를 PDF로 인쇄할 수 있는 화면.

**AI 사용 기록 (평가용)**
- 웹앱 안의 AI: 위의 프롬프트 입력칸 방식으로 프롬프트와 답변이 자동 수집된다.
- 외부 AI(Claude, Gemini 등)를 따로 쓴 경우를 위해 "외부 AI 사용 기록" 입력란을 보조로 둔다.
  1. 내가 쓴 프롬프트
  2. AI 답 중 채택한 부분
  3. 내가 검증하거나 고친 점
- 보고서 화면에 "AI 사용 기록은 평가에 반영됩니다" 안내를 항상 표시한다.

## 4. 시트 구조 (Apps Script가 생성)

| 시트 | 열 |
|---|---|
| `measurements` | timestamp, groupCode, L, amplitude, sensorAxis, nPeriods, T_mean, T_std, rawDataLink(또는 압축 JSON), note |
| `reports` | timestamp, groupCode, section, content, submitted |
| `ai_logs` | timestamp, groupCode, source(in-app/external), section, prompt, attachedContext(초안/분석결과/없음), response(or adopted), verification |
| `quiz` | timestamp, groupCode, question, answer (정리 질문) |

- 원본 센서 데이터는 셀 크기 제한을 넘을 수 있으므로 압축하거나 Drive 파일로 저장하고 링크만 시트에 남긴다.

## 5. 개인정보와 보안

- 학생 이름, 학번, 이메일을 저장하지 않는다. 조 코드로만 구분한다.
- API 키는 Apps Script Script Properties에만 둔다.
- AI 프롬프트에 개인정보를 넣지 말라는 안내를 표시한다.

## 6. 개발과 테스트

- **시뮬레이션 모드 필수:** 폰이 없어도 개발·테스트할 수 있도록 가상 진자 데이터(L, 진폭, 잡음, 샘플 간격 흔들림 지정)를 생성하는 버튼을 둔다.
- 확인 기준
  - L = 1.00 m 시뮬레이션에서 T ≈ 2.006 s(소진폭)가 1% 이내로 계산될 것
  - 가속도 축으로 계산해도 T/2를 반영해 같은 T가 나올 것
  - L을 0.5, 0.7, 0.9, 1.1 m로 바꾼 시뮬레이션 데이터에 오프셋 d = 0.08 m를 더했을 때 T²–L 기울기로 g ≈ 9.8이 나오고 절편으로 d가 복원될 것
  - iOS Safari와 안드로이드 Chrome에서 권한 요청과 센서 수집이 될 것
  - 노트북에서 마우스 툴팁, 폰에서 터치 툴팁이 될 것
- UI는 한국어, 고등학생이 처음 봐도 따라 할 수 있게 단계별 안내를 표시한다.
