## 7단계 → 가설연역 6단계 다시 놓기

패널(HTML `section.step-panel[data-step]`)은 **한 벌만** 둔다. 가설연역일 때는 같은 패널들을 묶어서 다른 단계 이름·순서로 보인다.

| 가설연역 단계 (키) | 보이는 7단계 패널 | 새로 넣을 칸 (PR 2) |
|---|---|---|
| ① 문제 인식 (`problem`) | 1 목적 | 관찰·궁금한 점 → **탐구 문제** 한 줄 |
| ② 가설 설정 (`hypothesis`) | 2 이론 | **가설 쓰는 칸** ("만약 ~하면 ~할 것이다, 왜냐하면 ~") |
| ③ 탐구 설계 (`design`) | 3 준비물 + 4 과정 (한 화면에 위아래로) | **변인 정리** (바꾸는 것·재는 것·같게 할 것) |
| ④ 탐구 수행 (`perform`) | 5 데이터 | — |
| ⑤ 자료 해석 (`interpret`) | 6 결과 | — |
| ⑥ 결론 도출 (`conclude`) | 7 결론 | **가설 판정** (지지 / 기각 / 판단 못 함 + 근거 데이터) |

- 단계 묶음 정의는 한 곳: `js/lab-ui.js` 의 `LabUI.FLOWS` (`report` = 7단계, `hd` = 위 표). 교사 화면 이름은 `js/class-cloud.js` 의 `STEPS_HD`(같은 키·이름).
- 패널 안 '다음: 3. 준비물 →' 같은 단추(`data-go="materials"`)는 그 패널이 들어 있는 가설연역 단계로 간다. 같은 단계 안의 패널(준비물→과정)을 가리키면 그 패널로 스크롤. 단추 글자는 가설연역이면 `다음: ③ 탐구 설계 →` 처럼 단계 이름으로 바꾼다(이전·다음 짝을 단계 순서대로 다시 씀).
- 패널의 큰 제목(`1. 목적`)은 가설연역이면 `① 문제 인식 — 1. 목적` 처럼 앞에 단계 이름을 붙인다 (원래 글은 그대로).

## 새 칸 저장 (PR 2, 구현함)

- 가설·탐구 문제·변인·가설 판정은 보고서 AI 부품(`js/report-ai.js`)의 **항목(sections)** 으로 넣는다 → 이 기기 자동 저장 + 수업이면 `labClasses/{수업}/reports/{조코드~uid}` 의 `sections` 에 같이 저장. 규칙(`okReport`)은 항목 이름을 막지 않고 개수만 12개까지라 **규칙을 바꾸지 않아도 됨** (7단계 4개 + 가설연역 4개 = 8개).
- 보고서 AI 항목 (가설연역): **가설 · 탐구 설계 · 자료 해석 · 결론·가설 판정** (`hypothesis`·`design`·`analysis`·`verdict`). 7단계는 지금 그대로(이론·방법·데이터 분석·결론 및 검토). 이미 쓴 글은 키가 남아 있어 방법을 바꿔도 지워지지 않는다.
- 가설 칸은 ② 단계, 변인은 ③, 판정은 ⑥ 에 그 자리에서 쓰고(ReportAI 가 그 칸을 보여 줌), ⑥ 결론의 AI 피드백 묶음에서 다시 볼 수 있게 한다.
- 구현: `js/report-ai.js` 의 `HD_SECTIONS` = 탐구 문제(`problem`, ① 목적 패널) · 가설(`hypothesis`, ② 이론 패널) · 탐구 설계(`design`, ③ 과정 패널) · 자료 해석(`analysis`, 7단계 '데이터 분석'과 같은 글) · 결론·가설 판정(`verdict`, ⑥ 결론 패널, 지지/기각/판단하기 어려움 고르기 = 글 첫 줄 `[판정] 지지`). 쓰기 칸(`.rai-inline`)과 보고서 탭의 글은 같은 것. 진행 방법을 바꾸면(`lab-flow` 이벤트) 보고서 탭이 그 방법 항목만 보이고 쓰기 칸은 가설연역에서만.
- 선생님이 만든 실험: '학생 화면 방식'에 **가설연역 6단계**(`layout: 'hd'`). 방법은 만들 때 고른 것으로 고정(수업 방법·학생 고르기보다 먼저). 이 실험에는 아직 보고서 AI 가 없어서 쓰기 칸도 없음(다음).

## 누가 고르나 · 어디에 저장

- **수업**: 수업 문서 `labClasses/{수업}` 에 `flow: 'hd'` (7단계는 칸 없음 = 예전 수업과 같음). 수업 만들기에서만 고르고 만든 뒤에는 바꾸지 않는다 → 규칙 create 허용 칸에 `flow`(값은 `'report'|'hd'`), update 허용 칸에는 넣지 않음 **(규칙 바뀜)**.
  고를 수 있는 실험은 `ClassCloud.EXPS` 에 `flows: true` 가 붙은 것만 (PR 1 은 퀀텀닷, PR 2 에서 나머지).
- **수업 없이 연 화면**: 단계 탭 위 '진행 방법: 📋 7단계 / 🔍 가설연역' 고르기, 이 브라우저에 기억(`lab-flow`, 모든 실험 공통). 수업으로 들어오면 수업 방법을 따르고 고르기는 숨김.
- 📱 폰 측정 화면(`?role=phone`)은 측정 단계만 쓰므로 고르기를 보이지 않는다 (방법은 따르되 시작 단계 = 측정 단계).

## 깨지면 안 되는 것

| 것 | 어떻게 지키나 |
|---|---|
| 예전 수업 (flow 없음) | 7단계 그대로 |
| 주소 `#step-N` | 그 방법의 N 번째 단계 (가설연역이면 1~6) |
| 저장된 진행 `lab-steps:<key>` | 7단계는 그대로, 가설연역은 `lab-steps:<key>:hd` 따로 |
| ReportAI 에 쓴 글 | 항목 키를 지우지 않음 |
| ClassShare 하트비트 단계 | 실험 쪽 `getStep` 이 패널 키를 보내는 페이지(퀀텀닷의 `state.tab` 등)는 그대로 — 교사 화면은 수업 방법을 보고 패널 키 → 가설연역 단계 이름으로 바꿔 보여 줌 (`ClassCloud.stepName(exp, step, flow)`) |
| 교사 '▶ 다음 단계 열기'·🎬 발표 보기 | `ClassCloud.gateSteps(exp, flow)`·`stageInfo(exp, stage, flow)`: 가설연역이면 6단계 키, 수업 문서 `stage` 는 지금처럼 **번호**. 학생 화면 잠금(`js/class-share.js` applyGate)도 수업 방법의 단계 키로 |
| 📱 폰 측정 화면 | 잠금 없음·측정 단계에서 시작 (지금과 같음) |

## 메인 화면

묶음은 그대로, 카드 제목 옆에 작은 교과 배지(`span.badge`): 물리(플랑크·이상기체·말루스·전자기 유도·자유낙하·진자), 물리·화학(양자점, 이상기체는 '물리·화학'?—물리로 둠), 생명·보건(심박수·데이터 가공 실험실), 정보(데이터 가공 실험실·걷기·뛰기), 가족 행사는 배지 '가족 행사'. 센서 값 바로 보기 카드는 배지 없음.

2. **PR 2**: 플랑크·이상기체(자체 `nav.tabs` → 공통 `initSteps` 로 옮기거나 같은 묶기), 말루스·전자기 유도·자유낙하·진자, 선생님이 만든 실험('학생 화면 방식'에 가설연역), 새 칸(탐구 문제·가설·변인·가설 판정)과 보고서 AI 항목.
