# 가상 수업 기록 (교사 역할) ⑨ 스마트폰 카메라 심박수(숨 참기 탐구) · 데이터 가공 실험실

- 돌린 날: 2026-11-20 · 기준: `main` 9a89865
- 방법: 교사 1920×1080(= 4K 배율 200 %), 조 노트북 1366×768, 폰 Pixel 7 흉내(가짜 카메라). 숨 참기는 `#breath-scale=0.2` 로 줄여 3초에 멈춤. 다시 돌리기: `node tools/virtual-class/teacher-heartrate.cjs <그림 폴더>`
- 한 것: 심박수 수업 만들기 → 진행 화면 → 1조 노트북 참여 → 1조 폰이 숨 참기 측정·보내기 → 노트북 결과 → 교사 조 카드·내려받기 → 데이터 가공 실험실을 프로젝터 크기로 열어 읽기.
- 하지 않은 것: 한 반 24명이 번갈아 재는 흐름, 30초·60초 비교, 데이터 가공 실험실 0~6 단계를 끝까지 조작(학생 세션 몫), 실제 맥파(가짜 카메라는 '손가락으로 덮어 주세요' 상태).

## 수업 시나리오 (고1~2 통합과학·생명·정보 24명 · 6조(노트북 1대 + 폰) · 2차시)

**1차시 — 숨 참기 탐구** (심박수 수업, 수업 코드로 참여)

| 분 | 교사가 하는 말·행동 (물음 → 힌트) | 학생(조) |
|---|---|---|
| 0~5 | 손목 맥박을 15초 세게 한 뒤 **"숨을 참으면 심장은 빨라질까, 느려질까? 왜 그렇게 생각하나?"** (답은 말하지 않음, 손 들기) | 노트북 참여, 예상 말하기 |
| 5~12 | 안전: 앉아서·관찰자·몸 상태, 힘들면 바로 멈춤(멈춘 것도 자료). **"무엇을 같게 두어야 30초와 60초를 견줄 수 있을까?"** 힌트: 자세·쉬는 시간·같은 사람 | 역할(측정·관찰·기록) 나누기 |
| 12~40 | 돌아다니며 손가락 덮기·신호 품질 확인 | 노트북 QR → 폰: 카메라 → 안전 확인 셋 → 안정 60초 → 숨 참기 30초 → 회복 60초 → 📤 보내기 → 노트북 곡선·지표 |
| 40~50 | **"변화율이 − 인 사람과 + 인 사람이 있네요. 무엇이 달랐을까?"** | 수업 분석 동의한 회차만 보내기 |

**2차시 — 데이터 가공 실험실** (수업 없이 각 조 노트북에서 `data-lab.html`)

| 분 | 교사 | 학생 |
|---|---|---|
| 0~10 | 예시 '선생님 실측 2 — 손가락 떨어짐'을 띄우고 **"같은 원본인데 앱은 37회, 여기서는 77회. 어느 쪽이 맞을까? 무엇이 달라서?"** | 예상 |
| 10~40 | 0 원천 → 6 결과를 한 단계씩, 단계마다 "이 설정을 바꾸면 최종 심박수가 어떻게 될까? (예측 → 바꿔 보기)" | 단계마다 ✏️ '무엇을 골랐고 왜?' 한 줄 |
| 40~50 | 6 결과: 기록 모음, 손목 맥박과 비교 | 기록 복사·인쇄 |

## 걸린 시간 (어림)

숨 참기 한 번 = 안정 60 + 숨 참기 30(~60) + 회복 60 = 2분 30초~3분, 준비·손가락 맞추기 포함 5분. 조마다 2~3명만 잴 수 있음(28분). 30초와 60초를 같은 학생이 비교하려면 사이에 3분 이상 쉬어야 해 1차시로는 빠듯.

## 막힌 곳 · 헷갈린 곳 · 개선 제안

### 상

1. **학생이 '수업 분석 동의'를 하기 전에 원본 측정이 교사 화면·내려받기에 들어온다**
   - 본 것: 폰에서 📤 보내기(노트북으로)만 했고 노트북의 '📤 동의한 회차 선생님께 보내기'는 **(0개)** 인데, 교사 조 카드에 '📤 제출: 1개 (🫁 숨 참기 30초 (3초에 멈춤)) · 참은 초 3.2', 교사 CSV·JSON 에 그 회차의 원본(`kind: raw` — 프레임별 밝기·노출, 여기서 심박 곡선을 다시 계산할 수 있음)이 한 줄로 들어 있음.
   - 왜 문제: 학생 화면은 "동의하지 않은 회차의 결과는 이 노트북에만 남아요", "보내기는 '수업 분석 동의'를 체크한 회차만 보내요"라고 말함. 계산된 결과(곡선·지표)는 정말 안 오지만 **원본은 수업 공간에 있으므로 교사가 받게 됨** — 건강 관련 자료의 동의 안내와 실제가 어긋남. 교사는 '제출 1개'를 동의한 제출로 읽게 됨.
   - 제안: ① 폰 → 노트북 원본은 그 조의 '짝 공간'으로만 보내고 수업 공간에는 동의한 결과만 ② 그게 어렵다면 교사 카드·내려받기에서 `raw` 는 빼거나 '🔒 동의 전(원본)'으로 따로 표시하고 학생 화면 문구를 사실대로("원본 숫자는 선생님 수업 공간에 저장돼요").

2. **심박수 수업에는 🎬 발표 보기도, 단계 열기도 없다**
   - 본 것: 진행 화면 윗줄이 '🔄 새로 보기 · 📱 QR 화면 · ✅ 수업 마치기'뿐. 다른 수업에 있는 '학생 화면에서 지금 열린 단계' 카드와 '🎬 발표 보기 (학생 화면)'가 없음(이 실험은 7단계가 아니라 '심박수 재기 / 숨 참기 탐구' 두 화면).
   - 왜 문제: 선생님 결정 "수업 진행하기에서는 학생의 화면이 보이도록 / 웹앱만으로 프레젠테이션을 대신"이 이 수업에는 적용되지 않음. 안전 안내(천식·심장 질환… 관찰 역할)·측정 순서를 프로젝터로 보여 줄 길이 교사 화면 안에 없어 학생용 페이지를 따로 열어야 함. 학생이 안전 설명 전에 숨 참기를 시작하는 것도 막을 수 없음.
   - 제안: 이 수업에도 발표 보기(폰 측정 화면을 폰 틀로) + 최소 두 단계(① 안전·재는 법 → ② 숨 참기 측정) 잠금.

### 중

3. **데이터 가공 실험실은 수업으로 만들 수 없다** — 수업 만들기 실험 목록에 없음(심박수만). 그래서 2차시에는 단계 열기·진행 보기·발표 보기가 모두 없고, 학생이 단계마다 쓴 '✏️ 무엇을 골랐고 왜?'와 최종 심박수를 교사가 모아 볼 수 없음(기록 모음은 복사·인쇄). 이 페이지가 수업 원칙(아래)에 가장 잘 맞는 만큼 아쉬움. → 수업 종류에 추가(0~6 단계 잠금, 조별 '고른 설정·최종 심박수' 표).
4. **교사 조 카드의 요약이 '참은 초'뿐** — 이 탐구의 핵심(안정 평균·변화율·회복 시간)은 학생이 동의해 보낸 뒤에야 올 텐데, 동의 전 원본 줄과 동의 뒤 결과 줄이 어떻게 구별되는지 이번에 확인 못 함(상 1 과 함께 정리 필요).
5. **조마다 1~4번 자리 줄** — 숨 참기는 '같은 학생의 30초·60초 비교'가 뼈대인데 폰은 노트북 자리(1조 1번)를 그대로 써서 누구의 회차인지 조 안에서도 구별이 회차 이름뿐. 이름을 안 받는 원칙 안에서 '측정자 A·B·C' 고르기가 있으면 비교가 쉬움.
6. **노트북 5. '👥 조 공유' 접기에 '📤 선생님께 보내기'와 숨 참기의 '📤 동의한 회차 선생님께 보내기'가 따로** — 어느 단추가 무엇을 보내는지 학생·교사 모두 헷갈림.

### 하

7. 학생 노트북 화면에 개발용 설명이 김: '원본 CSV 열: t_s(초), R, G, Y … phyphox CSV(Time·Luma·Shutter Speed·ISO)도…'.
8. 데이터 가공 실험실은 수업 없이 열어도 '📱 폰으로 측정해 보내기'에 조 코드(99-64-…)가 저절로 생김 — 'Firebase 전환' 세션이 고치는 중인 것(다시 올리지 않음).

## 4K 프로젝터 (3840×2160)

| | 배율 100 % | 150 % | 200 % |
|---|---|---|---|
| 큰 QR·진행 화면 | 로켓 기록의 표와 같음(같은 화면) | | |
| 데이터 가공 실험실: 본문 글자 | 14px = 화면 높이의 0.6 % | 1.0 % | 1.3 % |
| 데이터 가공 실험실: 내용 폭 / 화면 폭 | 22 % | 34 % | 45 % |

데이터 가공 실험실은 발표 보기가 없으므로 교사가 페이지를 그대로 띄우게 되는데, 본문 14px·폭 860px 고정이라 4K 에서는 화면 가운데 1/5~1/2 에 작은 글씨. Alt+B(1.35배)로도 0.8~1.8 %. 전·후 그래프가 이 수업의 전부이므로 그래프가 화면을 채우는 '크게 보기'가 필요.

## 수업 원칙으로 본 화면 (인과관계 · 비계 · 과학적 사고력 · 변인 통제 · 문제 인식)

| 원칙 | 잘 된 곳 | 끊기는 곳 · 제안 |
|---|---|---|
| 인과관계 | 숨 참기: 안정 → 숨 참기 → 회복을 끊지 않고 재어 **원인(숨 참기)과 결과(심박 변화)가 한 곡선**에 보임(회색 = 숨 참기 구간, 점선 = 안정 평균). 데이터 가공: 단계 설정을 바꾸면 아래 단계와 최종 심박수가 바로 바뀜 — 원인 → 결과를 직접 조작 | 숨 참기 화면에 '왜 그럴까'(잠수 반사 등)를 묻는 자리가 없음 — 지표(변화율·회복 시간)만 나옴. 결과 아래에 '내 예상과 같았나요? 왜 그랬을까요?' 한 칸 |
| 비계 | 데이터 가공: 단계마다 '전 → 후' 그래프, '💡 배울 점', '✏️ 무엇을 골랐고 왜? (한 줄)', '기본 설정과 비교' — 본 실험 가운데 가장 촘촘함. 숨 참기: 안전 확인 셋을 체크해야 시작, 큰 카운트다운 | 데이터 가공의 '배울 점'이 **조작하기 전에 이미 보임**(답이 먼저) → 설정을 한 번 바꿔 본 뒤 펼쳐지게. 교사가 조별로 어느 단계에서 무엇을 골랐는지 볼 수 없음(중 3) |
| 변인 통제 | 숨 참기: 30초/60초만 바꾸고 안정·회복 60초는 고정, '30초 뒤 충분히 쉬고(3분 이상)', 선택 항목(운동 습관·체격 구간)으로 사람 사이 비교. 데이터 가공: **한 번에 설정 하나를 바꿔 최종 값이 얼마나 바뀌는지** 보는 구조 자체가 변인 통제 연습 | 숨 참기에서 '같게 둔 것'(자세·직전 활동·카페인 등)을 적는 칸 없음 → 함께 적는 항목에 '직전에 한 일' 고르기 |
| 문제 인식 | 데이터 가공 첫 화면의 '그때 앱이 낸 값 37.2회/분' ↔ 지금 77 — **어긋남에서 문제를 스스로 보게 함**(아주 좋음) | 숨 참기 탐구는 탐구 문제가 제목으로 주어짐. 측정 전에 '빨라질까 / 느려질까 / 그대로' 고르기 하나(예측)가 있으면 문제 인식 + 예측 → 관찰 → 설명이 됨 |
| 과학적 사고 | 신뢰도 낮은 구간을 빼고 그림, 회복 판정 기준(±5 %), 멈춘 것도 자료, 손목 맥박과 비교, 원본도 '요약'이라는 0 원천 | 조·반 전체로 견줄 재료가 교사 화면에 없음(아래) |

## 학생과의 상호작용

- **교사가 띄울 화면이 없다**(상 2): 발표 보기가 없어 안전 안내·재는 법을 함께 보려면 학생 페이지를 따로 열어야 함. 노트북에서 열면 측정 부분이 숨겨져(분석만) 폰 화면의 안전 확인·카운트다운은 보여 줄 수 없음.
- **반 전체 결과를 모아 볼 화면이 없다**: '변화율이 − 인 사람과 + 인 사람'을 한 그래프(가로: 참은 초, 세로: 변화율, 점 = 회차, 운동 습관별 색)로 띄우면 이 탐구의 토의가 됨. 동의한 결과가 교사에게 오므로 자료는 있음. 건강 자료이므로 **개인이 드러나지 않게**(조·번호 없이 점만) 띄우는 것이 조건.
- **말투·글 양**: 폰 화면은 짧고 말을 거는 꼴('의자에 앉아 있어요' 체크, '멈춘 것도 정상 자료예요(실패가 아님)') — 알맞음. 노트북 화면은 설명·예외 안내가 길고(원본 CSV 열 설명, 저장소 설명) 물음이 없음. 데이터 가공 실험실은 '~예요' 체로 짧게 끊고 숫자로 말해('숫자 약 187백만 개가 1초에 90개로') 고등학생에게 알맞음.
- **교사용·개발용이 섞인 곳**: 학생 화면의 CSV 열 설명·phyphox 안내·'🧪 카메라 없이 시뮬레이션'.
- **숨어 있는 좋은 것**: 데이터 가공 6 결과의 '기록 모음'(단계마다 고른 것과 까닭) — 조끼리 견주면 "같은 원본인데 왜 최종 값이 다른가"라는 가장 좋은 토의 거리인데 복사·인쇄로만 나옴.

## 가설연역

심박수 수업은 '진행 방법'(7단계/가설연역) 고르기가 없음(7단계 실험이 아님). 숨 참기 탐구는 내용상 가설연역에 잘 맞으므로(예상 → 설계(30/60초) → 측정 → 판정) 나중에 고려할 만함.

## 잘 된 것

- 폰 안전 확인(셋 다 체크해야 시작)·경고 글·'■ 숨 참기 멈춤', 폰에서는 결과를 숨기고 노트북이 계산, 노트북에 '🆕 폰에서 새 회차 1개가 들어왔어요. 숨 참기는 아래 … 에 있어요'.
- 데이터 가공 실험실의 단계 구조와 '무엇을 골랐고 왜'.

## 실제 기기 확인 필요

- 실제 폰 카메라로 2분 30초 이어 재기(손가락 힘·노출 잠금), 한 반이 동시에 원본(회차마다 수만 자)을 보낼 때 저장소 한도, 학교 개인정보 지침(건강 정보·동의).
