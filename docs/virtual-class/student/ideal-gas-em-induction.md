# 가상 수업 ⑦ 이상기체 상태 방정식 · ⑧ 전자기 유도 — 학생 쪽 기록

- 날짜: 2026-11-20 · 대상 `projects/ideal-gas.html`, `projects/em-induction.html` (main `9a89865`)
- 방법: Playwright + 가짜 저장소. 두 실험 모두 노트북에서 센서(블루투스 Pico / USB 아두이노)로 재는 실험이라 **센서 연결은 전혀 못 함(실제 기기 확인 필요)**. 화면이 주는 다른 길로 감: 이상기체는 '직접 입력', 전자기 유도는 '🧪 시뮬레이션'.
- 스크립트: `tools/virtual-class/student-sensor-labs.cjs` (둘 다 약 1분, 뒤에 `idealgas`·`eminduction` 을 붙이면 하나만)
- 어림한 시나리오(교사 시나리오 전): 2반 2조, 조마다 노트북 1대, 단계가 모두 열린 수업에 QR 로 들어와 5 데이터 → 6 결과 → 7 결론. 보고서·AI 는 ② 와 같은 부품이라 다시 하지 않음. 1~4 단계는 읽지 않음(대충 하는 학생).

## ⑦ 이상기체

### 한 일

1조 노트북: QR → 1조 1번 → 5 데이터 → 실험 1(보일): V·P·t 를 손으로 5점 + 소수점 잘못(55 를 5.5 kPa) 1점 → 실험 2(샤를·게이뤼삭) 화면만 봄 → 6 결과 → 7 결론.

### 잘 된 것

- 블루투스가 안 되는 브라우저에서 '센서 값을 보고 직접 입력하세요'로 바로 길을 줌. 기록하면 '기록했습니다: V = 110 mL, P = 5.50 kPa …'가 바로 나오고 표에 PV 가 계산됨.
- 6 결과가 풍부함(PV 평균·변동 %, V–1/P 절편, ln P–ln V 기울기, 몰수, '0 이면 이상적' 같은 읽는 법). '결과 정리' 쓰기 칸과 7 결론의 '가설(1번 탭)과 결과 정리(6번 탭)를 썼다' 점검 — **1 목표 단계에 가설을 쓰는 자리가 있는 유일한 7단계 실험**(예측 → 관찰 → 설명이 이어짐).

### 고칠 점

**상**

1. **7 결론에 '인쇄할 보고서에 넣을 학번·이름' 칸이 있음**(이 노트북에만 저장, 칸 3개: 학번·이름·모둠원으로 보임). 사이트 원칙('학생 이름·학번은 받지 않아요')과 바로 아래 📝 보고서의 '🔒 이름·학번 … 넣지 마세요'와 어긋남. 학교 노트북을 여러 반이 돌려 쓰면 앞 반 학생 이름이 남음. → 칸을 없애고 인쇄물에 손으로 쓰게, 또는 인쇄할 때만 묻고 저장하지 않기.
2. **7 결론에 쓸 곳이 세 겹**: '결론' 칸 + '검토(분석 질문)' 5칸('보고서(쓴 글)는 보내지 않습니다. 인쇄해서 내세요') + 📝 보고서 쓰기(4항목, 선생님께 저장·최종 제출). '📤 측정값 선생님께 보내기'·'🖨️ 보고서 미리보기·인쇄'·'📤 최종 제출'·'🖨️ 인쇄 (PDF)'가 한 화면(3.8장)에. 어느 것을 내야 하는지 화면만으로는 알 수 없음(②③⑤ 와 같은 문제, 여기가 가장 심함).

**중**

3. **말이 안 되는 값이 그대로 기록됨**: 5.5 kPa(55 의 잘못)가 경고 없이 들어가 PV 변동 43 %, R² 0.46, ln 기울기 −3.5 가 됨. 6 결과에는 '어느 점이 튀는지' 표시가 없음. → 앞 점들과 크게 다르면 '맞나요?', 6 결과 표에 튀는 줄 표시.
4. **5 데이터 맨 위 '👥 조 공유' 칸이 측정보다 위**(2.7장) — ②③ 과 같음. 띠의 '자동으로 나눠요'와 달리 '📤 선생님께 보내기'를 눌러야 감(③ 의 1번과 같음).
5. **실험 2 는 '자동 기록'이 주인데 센서가 없으면 '✅ 지금 값 한 번 기록'을 손으로 되풀이해야 함** — 직접 입력으로 온도·압력을 여러 번 넣는 길이 길고, 실험 1 → 2 로 넘어가라는 안내(언제 2 를 하는지)가 5 데이터에는 없음.
6. **'이 브라우저는 블루투스 연결을 지원하지 않습니다 (Android·PC 의 Chrome·Edge, https 필요)'** — 학생에게는 '크롬이나 엣지로 여세요'면 충분.

**하**

7. 입력 칸 높이 35~38px(V·P·t, 학번·이름).
8. 6 결과가 3.3장 — 실험 2 를 안 했어도 빈 그래프 3·'실험 2 기록이 없습니다'가 자리를 차지.

## ⑧ 전자기 유도

### 한 일

1조 노트북: QR → 1조 1번 → 5 데이터 → 🧪 시뮬레이션 → ● 측정 시작(5초) → 💾 이 측정 저장(이름 묻는 창) ×2 → 📤 선생님께 보내기 → 6 결과 → 7 결론.

### 잘 된 것

- '🧪 시뮬레이션 (센서 없이 체험)' 단추 하나로 흐름 전체를 해 볼 수 있음. 측정 → 저장 → 6 결과의 봉우리·렌츠 순서·∫ε dt·ΔΦ·측정 비교 표까지 끊김 없음.
- 7 결론의 분석 질문이 좋음(속도를 바꿔도 넓이가 같은 까닭, N 을 두 배로 하면 무엇이 두 배, '코일 전압'은 단자 전압이라는 점) — 다음 측정을 하게 만드는 물음.
- 보내기: '✅ 보냈습니다: 측정 2개'.

### 고칠 점

**상**

1. **시뮬레이션 측정이 진짜 측정처럼 저장·전송됨.** 저장한 측정 이름·표·보낸 자료 어디에도 '시뮬레이션' 표시가 안 보임(④ 진자는 '🧪 시뮬레이션'이라고 적힘). 아두이노가 안 되는 조가 시뮬레이션으로 채워 내면 교사는 구별할 수 없음. → 이름 앞에 🧪, 교사 표에도 표시.

**중**

2. **측정을 저장할 때 브라우저 입력 창(prompt)으로 이름을 물음** — 다른 화면과 모양이 다르고, 취소하면 저장이 되는지 알 수 없음(못 봄).
3. **'💾 이 측정 저장'을 안 누르면 6 결과 비교 표·보내기에 안 들어감.** 측정 뒤 화면에는 '501개 샘플 · 결과는 6. 결과 단계에'만 나와, 저장을 건너뛰고 6 으로 가기 쉬움(마지막 측정 그래프는 보이지만 보내지지 않음).
4. **5 데이터 설정 칸이 어려움**: '전압 이득(PGA) ±256 mV …', '션트 저항', '샘플링 101 Hz' — 4 과정에 풀이가 있어도 측정 화면에서는 풀이 없이 나옴. 영점 보정을 안 해도 측정이 됨(점검 목록에만 있음).
5. **5 데이터 맨 위 조 공유 칸**(2.3장), '자동으로 나눠요' 띠와 손으로 보내기 — ③⑦ 과 같음.

**하**

6. 입력 칸 38px(N·R·측정 시간). 7 결론 맨 아래 '처음으로: 1. 목적'.

## 수업 원칙으로 본 것 (두 실험)

1. **왜 이 측정을 하는지** — 이상기체: 5 데이터의 실험 1·2 설명 한 줄씩으로 알 수 있음. 전자기 유도: 5 데이터에는 설정과 단추뿐이라, 1~4 를 안 읽으면 '자석을 코일에 넣는다'는 것조차 화면에 없음.
2. **막혔을 때 도움** — 이상기체: 센서가 안 되면 직접 입력으로 안내(답을 줌). 전자기 유도: 시뮬레이션으로 안내. 값이 이상할 때는 둘 다 말이 없음.
3. **변인을 스스로** — 이상기체: 감압/복귀를 고르고 V 를 정함. 전자기 유도: N·속도·높이를 바꿔 '각각 저장해 비교'하라는 점검 목록이 있으나, 무엇을 바꿨는지는 측정 이름에 스스로 적어야 함(바꾼 조건을 적는 칸이 따로 없음).
4. **탐구 문제를 스스로** — 이상기체는 1 목표에 가설 칸이 있음(좋음). 전자기 유도는 없음.
5. **예측 → 관찰 → 설명** — 이상기체는 가설 → 측정 → 결과 정리 → 결론으로 이어짐. 전자기 유도는 관찰 → 설명(분석 질문)은 좋으나 예측 자리가 없음('빠르게 넣으면 봉우리가 어떻게 될까?'를 먼저 묻지 않음).

## 상호작용

- **화면이 말을 거는가**: 둘 다 5 데이터에서 값·그래프가 바로 반응. 6 결과는 읽기가 김(이상기체 3.3장). 7 은 쓰기.
- **조원끼리**: 노트북 1대에 센서 1개 — 한 명이 조작, 나머지는 펌프·주사기·자석. 역할 안내는 없음. 조원 폰으로는 할 일이 없음.
- **다른 조와 견주기**: 없음(전자기 유도의 '저장한 측정 비교'는 우리 조 안).
- **맞지 않는 말**: '사이트 저장소', '구글 로그인 없음', '이 수업 공간', 'PGA', 브라우저·https 안내.

## 실제 기기 확인 필요

- Pico 환경 센서 블루투스 연결·자동 기록(이상기체), 아두이노 USB 연결·영점 보정·진짜 자석 파형(전자기 유도), 학교 노트북의 크롬 Web Bluetooth/Web Serial 권한 창
