가속도계 데이터 분석

상태: 연결 대기

센서 준비 안내 (Thonny · BLE 검색 v2)

Pico-Environment-Sensor의 IMU를 사용합니다. I2C0: SDA GP20, SCL GP21, 주소 0x68. ICM-20948 또는 MPU-9250/9255를 칩 ID로 확인합니다. 측정값은 중력을 포함한 가속도(g), 최대 범위는 축별 ±16g입니다. 정지 상태에서 Total은 약 1g이며 축 방향은 보드에 따라 다릅니다.

이 장치용 MicroPython을 설치하고 Thonny에서 다음 네 파일을 Pico 루트에 저장한 뒤 main.py를 실행하세요. 기존 main.py와 imu.py도 새 버전으로 교체해야 합니다. ±16g 설정은 최신 imu.py에 적용됩니다.

main.py · bme280.py · imu.py · extra_sensors.py · 상세 안내

PC/Android Chrome·Edge에서 PicoEnv-XXXX를 선택합니다. 환경 실험 연결을 먼저 해제하세요. Wi-Fi 설정은 필요 없습니다. 선택 속도는 목표 전송 속도이며 실제 간격은 BLE 환경에 따라 달라집니다. 시간축은 Pico 측정 시각을 사용합니다. Cloud 제출은 요약만 저장하며 원시 값은 CSV로 보관하세요.

검색이 안 되면 최신 main.py를 다시 저장하고 Thonny → 보기 → 셸에서 F5로 실행하세요. 5초마다 [STATUS] ... BLE=ADVERTISING이 나오면 검색 대기 상태입니다. [FATAL]은 실행 오류, [STOP]은 정지 상태입니다. 검색 중에는 Thonny의 중지 버튼을 누르지 마세요. USB 시리얼 모니터 안내

2g 부근에서 측정이 제한되면 최신 imu.py와 main.py를 Pico 내부에 덮어쓰고 재시작하세요. 셸에 driver=impact-200-v3와 +/-16g VERIFIED가 표시되어야 합니다. 범위·필터 검증 실패 시 측정을 중단합니다.

200Hz는 목표 5ms 간격입니다. 최신 main.py와 imu.py를 장치에 저장하고 재시작하세요. 200Hz에서는 필터 대역폭을 ICM-20948 약 111Hz, MPU-9250/9255 약 99Hz로 높입니다. 다른 속도에서는 기존 약 45~50Hz 필터를 유지합니다. 넓어진 대역폭은 잡음과 앨리어싱 위험도 높입니다. 수 ms 충격의 최대값·축별 ±16g 초과는 정확히 복원할 수 없습니다. 200Hz에서는 장치 RAM에 10개(약 50ms)를 모아 전송하며 BLE MTU가 작으면 분할 후 웹에서 재조립합니다. 중지 시 남은 샘플도 전송합니다. 센서 하드웨어 FIFO 방식은 아니므로 전송 중 지연은 여전히 발생할 수 있습니다. 아래 간격 경고와 CSV 측정 시각을 확인하세요.

환경 페이지에서 보이던 장치가 여기서 보이지 않으면 환경 페이지의 연결 해제를 먼저 누르세요. Thonny에 BLE=ADVERTISING이 표시된 뒤 검색합니다. 이전 페이지가 남아 있으면 Ctrl+Shift+R로 강력 새로고침하세요.
